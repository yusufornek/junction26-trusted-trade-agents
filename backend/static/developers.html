Connect your procurement agent

Start with an operator-issued sandbox credential. The operator provisions the scenario and provides its base URL, customer scope and any buyer mandate. Use an isolated sandbox deployment with its own database, signing keys, credentials and policy; set GATEWAY_ENVIRONMENT=sandbox. Do not point scenario clients at live demo storage. Orders are fixed-price, gateway-simulated; no order is sent to Valio Aimo.

Endpoints and authentication

REST base: {{BASE_URL}}/v1. MCP Streamable HTTP: {{BASE_URL}}/mcp (POST JSON-RPC; GET is the protocol stream, not a card). A2A 1.0 JSON-RPC: {{BASE_URL}}/a2a with A2A-Version: 1.0. Public discovery begins at AI catalog. Use TLS in production and configure GATEWAY_PUBLIC_URL to the public origin so MCP accepts its Host and Origin. Runtime tools/list and initialize are authoritative; the draft server card is advisory.

Every private HTTP call, including MCP initialize, needs Authorization: Bearer $AGENT_TOKEN. X-Agent-Id grants no authority. An optional buyer-issued VC-JWT goes in Agent-Mandate on each request. GET /v1/me and MCP get_agent_context show only your principal, customers, standing constraints, effective limits, rolling budget and supported operations. Operator and buyer approver credentials are separate from agent credentials.

Procurement rules

A need requires customer_id, intent, quantity {value, unit} and deliver_by. Units are L, KG or SALES_UNIT. Values are strict positive numbers up to 1,000,000. deliver_by is today through +60 days in Europe/Helsinki. Explicit quote quantities are whole sales units, including KG, in allowed_lot_size steps with a minimum step of one. Do not treat a sales unit as one litre. Tool and field tables below carry the complete schemas.

Customer standing constraints are unioned with each request at lookup, quote, order and approval. Missing allergen evidence never proves absence. Hard constraints cannot be approved away. Preferences may produce substitutes requiring approval. Use a returned plan_ref, or explicit lines with need_ref from the stored lookup. Prices cannot be negotiated. Quotes expire at the earliest applicable price validity, future cut-off or 30 minutes. On REFRESH_QUOTE, create a new quote and inspect its fixed total.

Orders become CONFIRMED, PENDING_APPROVAL or REJECTED. Pending orders return next_action=WAIT_FOR_APPROVAL and poll_after_seconds. A human reviews the evidence_revision. Changed evidence produces REVIEW_UPDATED_EVIDENCE and must be reviewed again; pending orders may expire. Follow next_action, never infer recovery from error prose. RETRY_SAME_COMMAND means wait retry_after_seconds and resend identical arguments and idempotency key, including after a lost response. LOOKUP_REQUIRED means refresh lookup; FIX_REQUEST means correct schema fields; CONTACT_ADMIN means replace credentials or obtain scope; STOP means halt. REST failures use RFC 9457 application/problem+json, MCP uses isError and identical structured content. X-Correlation-Id links requests.

Lookup, mutation and read token buckets are shared across REST, MCP and A2A per principal. Default capacities/refill per minute are 60/60, 120/120 and 600/600; operator policy may tighten them. Read get_agent_context for effective buckets. RATE_LIMITED (429) and upstream 502/503 retry guidance carry intervals. Supplier calls are paced at 5/s; 429 pauses uncached calls for Retry-After (default 30 seconds). Cached results can continue.

REST walkthrough

Execute in bash with GATEWAY_URL and AGENT_TOKEN exported, jq installed and DELIVER_BY set to a date within 60 days. The response files are temporary. This example needs the full_stock fixture. Agent credentials cannot approve; an approver uses POST /v1/approvals/{id}/approve with approver and the current evidence_revision.

set -eu
CONNECT_DIR=$(mktemp -d)
curl --fail-with-body -sS "$GATEWAY_URL/v1/me" -H "Authorization: Bearer $AGENT_TOKEN" > "$CONNECT_DIR/me.json"
CUSTOMER_ID=$(jq -r '.customer_ids[0]' "$CONNECT_DIR/me.json")
jq -n --arg customer "$CUSTOMER_ID" --arg day "$DELIVER_BY" '{customer_id:$customer,intent:"lactose-free milk",search_terms:["milk"],required_claims:["FREE_FROM_LACTOSE"],exclude_allergens:["AE"],quantity:{value:10,unit:"L"},deliver_by:$day}' > "$CONNECT_DIR/need.json"
curl --fail-with-body -sS "$GATEWAY_URL/v1/offers" -H "Authorization: Bearer $AGENT_TOKEN" -H 'Content-Type: application/json' --data-binary @"$CONNECT_DIR/need.json" > "$CONNECT_DIR/offers.json"
jq --arg customer "$CUSTOMER_ID" --arg day "$DELIVER_BY" '{customer_id:$customer,deliver_by:$day,plan_ref:{lookup_id:.lookup_id,plan_index:0}}' "$CONNECT_DIR/offers.json" > "$CONNECT_DIR/quote-request.json"
curl --fail-with-body -sS "$GATEWAY_URL/v1/quotes" -H "Authorization: Bearer $AGENT_TOKEN" -H 'Content-Type: application/json' -H "Idempotency-Key: connect-quote-$(basename "$CONNECT_DIR")" --data-binary @"$CONNECT_DIR/quote-request.json" > "$CONNECT_DIR/quote.json"
jq '{quote_id:.id}' "$CONNECT_DIR/quote.json" > "$CONNECT_DIR/order-request.json"
curl --fail-with-body -sS "$GATEWAY_URL/v1/orders" -H "Authorization: Bearer $AGENT_TOKEN" -H 'Content-Type: application/json' -H "Idempotency-Key: connect-order-$(basename "$CONNECT_DIR")" --data-binary @"$CONNECT_DIR/order-request.json" > "$CONNECT_DIR/order.json"
ORDER_ID=$(jq -r '.id' "$CONNECT_DIR/order.json")
curl --fail-with-body -sS "$GATEWAY_URL/v1/orders/$ORDER_ID" -H "Authorization: Bearer $AGENT_TOKEN" > "$CONNECT_DIR/order.json"
curl --fail-with-body -sS "$GATEWAY_URL/.well-known/jwks.json" > "$CONNECT_DIR/jwks.json"
python clients/python/verify_receipt.py "$CONNECT_DIR/order.json" --jwks "$CONNECT_DIR/jwks.json" --customer "$CUSTOMER_ID" --agent "$(jq -r '.principal.id' "$CONNECT_DIR/me.json")"

Verify evidence

Keep the order JSON and JWKS. The independent verifier above checks detached Ed25519 JWS, customer, agent and gateway-simulated commitment. Tampered totals or status fail verification. A verified receipt proves this gateway's recorded decision, not supplier fulfilment. Signed quotes can also be verified offline with backend/scripts/verify_quote.py; retain quote.signature and its SHA-256 digest in the receipt. The authenticated order timeline and UBL export are at /v1/orders/{id}/timeline and /v1/orders/{id}/ubl.
