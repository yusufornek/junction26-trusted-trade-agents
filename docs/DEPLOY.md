# Single-instance deployment

Run one gateway process and one Caddy console on a Docker host. The console uses relative API URLs, so
the browser, REST clients and agent clients share one public origin. Only ports 80 and 443 are published;
the backend's port 8000 is private to the Compose network. This package does not add application routes:
MCP, A2A and developer paths are forwarded to the gateway when those features are present in the checkout.

## Local run and credential generation

Use Docker with BuildKit and Docker Compose v2 or later. Run every command below from the repository
root. Initial image builds need registry, PyPI and npm access. Node 20's current image supplies the
20.19+ version required by the existing Vite lockfile. Both build contexts are the repository root.
The Dockerfiles copy source directories explicitly so local `.env*`, `.venv`, `node_modules` and runtime
state are not copied into the images; the directory-local `.dockerignore` files only apply if those
directories are used as build contexts.

```sh
cp deploy/.env.example deploy/.env
chmod 600 deploy/.env
docker compose --env-file deploy/.env -f deploy/docker-compose.yml build
```

Generate operator and per-agent credentials without printing their values. This one-off container
bypasses the normal entrypoint (which requires an operator token) and does not mount the state volume.
Using the host UID/GID keeps the generated env file owned by your user on Linux:

```sh
docker run --rm --user "$(id -u):$(id -g)" --entrypoint python \
  --mount "type=bind,src=$PWD/deploy,dst=/bootstrap" \
  trusted-trade-backend:local \
  scripts/gen_keys.py --write --env-file /bootstrap/.env
```

Alternatively, with backend dependencies already installed locally:

```sh
backend/.venv/bin/python backend/scripts/gen_keys.py --write --env-file deploy/.env
```

The script adds missing credentials for the committed policy's agent IDs and preserves existing values.
Edit `deploy/.env` privately to fill the supplier and Decisions credentials, then start:

```sh
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d
docker compose --env-file deploy/.env -f deploy/docker-compose.yml ps
docker compose --env-file deploy/.env -f deploy/docker-compose.yml logs --tail=50 backend console
```

With `SITE_ADDRESS` blank, open `http://localhost` (or the VM's public IP). Sign in to the console with
the generated operator token; external agents use their own secret from `AGENT_KEYS` as a Bearer token.
Keep the env file private and out of version control. No credential is embedded in the frontend build.

The backend refuses startup without `OPERATOR_TOKEN`, builds the bundled catalog only when the database
file is missing, then starts Uvicorn on `0.0.0.0:8000` with one worker and proxy headers. The backend
healthcheck requires a populated catalog and makes no supplier calls. The console waits for backend
health; its own probe fetches the built `index.html` on a loopback-only Caddy listener at port 8080.
An unhealthy status alone does not restart a container; `unless-stopped` restarts an exited process.

## Environment

`deploy/.env.example` lists names only, with empty values. Supply these in `deploy/.env`:

| Variable | Meaning |
| --- | --- |
| `VALIO_API_BASE` | Set to `https://junction26.valioaimo.fi` for the challenge API. Fill this explicitly: an empty env value overrides the application's default. |
| `VALIO_API_KEY` | Challenge API credential for live price and availability calls. |
| `OPENAI_API_KEY` | Decisions provider credential for offer-fit judgments. |
| `OPERATOR_TOKEN` | Required operator secret; generated by `gen_keys.py`. |
| `AGENT_KEYS` | Comma-separated `agent-id:secret` pairs; generated by `gen_keys.py`. |
| `SITE_ADDRESS` | Blank means `:80`; set a bare DNS name such as `demo.example.com` for automatic HTTPS. |
| `GATEWAY_PUBLIC_URL` | Public HTTP(S) origin, e.g. `https://demo.example.com`, without a path. Set it in `deploy/.env` for remote MCP; Compose passes it to the backend. The root `.env.example` lists this variable. |
| `ANCHOR_RPC_URL` | Optional EVM JSON-RPC endpoint. |
| `ANCHOR_CHAIN_ID` | Optional anchoring chain ID, e.g. `137` for Polygon. |
| `ANCHOR_PRIVATE_KEY` | Optional funded anchoring wallet secret. |
| `ANCHOR_EXPLORER_TX_URL` | Optional explorer transaction URL prefix. |
| `ANCHOR_EVERY_N_ENTRIES` | Optional automatic anchor interval in audit entries. |

Leave all `ANCHOR_*` values blank to disable anchoring. Enabling it requires the RPC, chain, wallet and
explorer settings; the automatic interval is optional. Anchoring can spend the wallet's funds.
Compose reads `.env` into the backend and passes only `SITE_ADDRESS` to Caddy. Always include the shown
`--env-file deploy/.env`: it also supplies Compose's interpolation of `SITE_ADDRESS`.

The deployment workflow passes its `SITE_URL` as `GATEWAY_PUBLIC_URL` when restarting Compose. This keeps
the advertised MCP endpoint and the transport's trusted Host/Origin aligned with the deployed address.
Without this setting, connection responses advertise MCP only for loopback request hosts (`localhost`,
`127.0.0.1`, `[::1]`); an external request receives `mcp_url: null` and uses `rest_base_url` instead.
Disabling MCP with `create_app(..., serve_mcp=False)` also removes its catalog entry and server-card route.
Keep one gateway process per database; the MCP session manager runs in that process.

The backend image sets `DB_PATH=/data/app.db` and `SIGNING_KEY_DIR=/data/keys`. These new application env
overrides also work in repo-root `.env.local`; when absent (or empty), local paths retain their previous
defaults. In the image, `backend/var` is a symlink to `/data`, keeping the existing CLI tools on the same
persistent storage. Keep the image's paths for this Compose deployment:

| State | Container location | How the path is selected |
| --- | --- | --- |
| SQLite database and WAL/SHM sidecars | `/data/app.db`, `/data/app.db-wal`, `/data/app.db-shm` | `DB_PATH` |
| Editable runtime policy | `/data/policy.yaml` | Parent of `DB_PATH`; falls back to the committed `backend/policy.yaml` |
| Gateway signing keys | `/data/keys/` | `SIGNING_KEY_DIR`; otherwise parent of `DB_PATH` plus `keys` |
| Buyer issuer keys | `/data/buyer-keys/` | Existing `backend/var/buyer-keys` CLI default through the symlink |
| Demo reset archives | `/data/archive/` | Parent of `DB_PATH` plus `archive` |

The named volume `trusted-trade_gateway_data` preserves all of this across container replacement.
The backend runs as UID/GID 10001; a fresh volume receives the image directory's ownership. Caddy uses
separate `trusted-trade_caddy_data` and `trusted-trade_caddy_config` volumes for certificates and config.
For manual key rotation or mandate issuance, use `docker compose ... exec backend python
scripts/rotate_key.py` or `scripts/issue_mandate.py`; their defaults resolve into the persistent volume.

## Deploy on a single VM

1. Provision a Linux VM with Docker, Compose, outbound HTTPS and enough disk for the catalog and archives.
   Copy or clone this repository, including `data/`, `contracts/`, `backend/vendor/` and the frontend lockfile.
   Copy credentials separately into `deploy/.env`, or generate them there using the steps above.
2. For HTTPS, point the public DNS name's A/AAAA records at this VM and set `SITE_ADDRESS` to that bare
   domain. Permit inbound TCP 80 and 443 in the VM and cloud firewall. Caddy obtains and renews the
   certificate automatically and redirects HTTP to HTTPS. For an IP-only demo, leave `SITE_ADDRESS` blank
   and use plain HTTP on port 80.
3. From the repo root, run `docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build`.
   After the initial build, `docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d`
   reuses the images. Inspect `ps` and logs, open the public URL and `/health`, sign in, and complete a
   lookup → quote → order → approval demo. Check `/docs` and the discovery endpoints implemented by this
   checkout from that same origin. Backend 404s on unimplemented protocol paths are forwarded unchanged.

For a VM without build-time network access, build the two tagged images on a networked machine with the
VM's architecture, transfer them with `docker save` / `docker load`, then use the same Compose file with
`up -d --no-build --pull never`. Live supplier, Decisions and optional anchoring calls still require
outbound connectivity at runtime.

## Reset the demo

Stop the gateway before resetting, even with `--force`. A one-off container uses the same image, env and
volume; bypass its startup entrypoint so only the reset runs. Stop the console too during maintenance:

```sh
docker compose --env-file deploy/.env -f deploy/docker-compose.yml stop console backend
docker compose --env-file deploy/.env -f deploy/docker-compose.yml run --rm --no-deps \
  --entrypoint python backend scripts/reset_demo.py --force
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d
```

The reset archives the old database, SQLite sidecars and runtime policy under `/data/archive/<UTC timestamp>/`
and rebuilds the catalog offline. New orders and audit entries start empty and policy falls back to committed
defaults. Signing and buyer keys stay in place. Retain the archive to preserve the previous audit chain.

## Back up and restore

Stop writers for a consistent snapshot, then copy the whole volume, including keys, runtime policy,
database sidecars and reset archives. This uses Python already in the backend image:

```sh
mkdir -p backups
chmod 700 backups
docker compose --env-file deploy/.env -f deploy/docker-compose.yml stop console backend
docker compose --env-file deploy/.env -f deploy/docker-compose.yml run --rm --no-deps -T \
  --entrypoint python backend -c \
  'import sys, tarfile; t = tarfile.open(fileobj=sys.stdout.buffer, mode="w|gz"); t.add("/data", arcname="data"); t.close()' \
  > backups/gateway-data.tar.gz
chmod 600 backups/gateway-data.tar.gz
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d
```

Use a fresh backup filename for each snapshot. Back up `deploy/.env` separately using private storage;
the volume backup does not include credentials from that file. Retain Caddy's volumes for certificate
continuity, or let Caddy reissue certificates after migration. Protect the gateway backup as private key
material.

To restore a trusted backup, first stop both services and take a backup of the current state. Replace
only the gateway volume; Caddy's volumes and the private env file remain in place:

```sh
docker compose --env-file deploy/.env -f deploy/docker-compose.yml stop console backend
docker compose --env-file deploy/.env -f deploy/docker-compose.yml rm -f backend
docker volume rm trusted-trade_gateway_data
docker compose --env-file deploy/.env -f deploy/docker-compose.yml run --rm --no-deps -T \
  --entrypoint python backend -c \
  'import sys, tarfile; t = tarfile.open(fileobj=sys.stdin.buffer, mode="r|gz"); t.extractall("/", filter="data"); t.close()' \
  < backups/gateway-data.tar.gz
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d
```

Restore archives produced by this deployment only. The new volume is initialized with UID/GID 10001;
extraction runs as the same non-root user. `docker compose down` retains named volumes;
`docker compose down -v` removes them, including keys and audit history.

## Single-instance rule and validation

Keep exactly **one backend container, one Uvicorn worker, one database, one in-process rate limiter and
one audit chain**. Do not scale the backend, run an independent MCP process against the same database,
or share this volume between hosts. Caddy forwards all supported interfaces to the same gateway.
Restarting resets the in-memory limiter but preserves database, policy, signatures and audit records.
Scaling requires a separate design for shared limits, serialized writes and audit consistency.

After a networked build, verify both healthchecks, public HTTP/HTTPS, SPA deep links, API authentication,
streaming protocol routes implemented by this checkout, the full buyer/approval flow, and persistence
after container recreation. Exercise reset and backup/restore on disposable demo state first.

- **Freeze before judging:** pushes deploy immediately. Before the demo, stop merging to `main` or disable the
